# OpenPortfolio 产品需求文档

**文档版本：** V0.1
**产品阶段：** 概念验证 / MVP
**产品类型：** 本地优先的全球投资资产管理工具
**发布方式：** GitHub 开源 + GitHub Pages
**目标用户：** 持有多市场、多账户、多币种资产的长期投资者

---

## 一、产品概述

OpenPortfolio 是一款面向长期投资者的、本地优先的全球资产管理工具。

它用于统一记录和统计分散在不同账户、不同市场和不同币种中的投资资产，例如：

* 中国 A 股券商账户
* 美国券商账户，例如嘉信理财
* 国内场外基金
* QDII 人民币份额
* QDII 美元份额
* 人民币现金
* 美元现金

用户可以录入股票代码、持仓数量、成本价格、基金份额、基金净值等信息，并通过行情、基金净值和汇率数据，计算当前市值、持仓盈亏以及人民币或美元口径下的总资产。

产品的核心不是提供高频交易行情，而是帮助长期投资者回答三个问题：

1. 我现在总共有多少资产？
2. 这些资产分布在哪些账户、市场和币种？
3. 我的持仓目前盈利或亏损多少？

---

## 二、产品背景

长期投资者的资产可能分散在多个平台中。

例如：

* A 股资产保存在国内券商。
* 美股资产保存在嘉信理财。
* QDII 基金保存在基金销售平台。
* 不同账户分别使用人民币或美元计价。
* 股票价格、基金净值和汇率的更新时间不同。

目前，大多数券商或基金平台只展示自身平台内的资产，无法形成统一的全球资产视图。

一些投资账本能够记录 A 股，但对美股、QDII 美元份额和多币种换算的支持不足。

因此，用户需要一套独立于券商、基金平台和国家市场的投资资产管理系统。

## 三、产品目标

### 3.1 核心目标

建立一个统一的资产视图，将不同账户、市场和币种中的资产汇总到同一个仪表盘中。

### 3.2 具体目标

产品需要支持：

* 记录多个投资账户。
* 记录 A 股和美股持仓。
* 记录场外基金持仓。
* 记录人民币份额基金和美元份额基金。
* 记录不同币种的现金资产。
* 计算单项资产市值。
* 计算持仓成本。
* 计算持仓盈亏。
* 按人民币统计总资产。
* 按美元统计总资产。
* 展示数据最后更新时间。
* 在断网时继续查看上次保存的数据。
* 将用户数据保存在本地设备中。
* 支持数据备份与恢复。

## 四、产品原则

### 4.1 本地优先

所有账户、持仓、成本和资产快照默认只存储在用户本地。

产品不要求：

* 注册账号
* 登录
* 云端数据库
* 上传持仓信息
* 自建服务器

### 4.2 隐私优先

持仓数量、成本价格、资产总额等均属于敏感数据。

除获取行情、基金净值和汇率外，产品不得主动向外部服务器上传用户的投资数据。

### 4.3 资产管理优先

本产品不是交易软件，也不是实时行情终端。

产品优先保证：

* 资产记录可靠
* 数据计算正确
* 多币种统计清晰
* 历史数据可追溯
* 外部行情接口可替换

不优先追求秒级行情刷新。

### 4.4 数据源可替换

任何免费行情接口都可能限流、变更或停止服务。

产品不得与单一数据源强绑定。

A 股、美股、基金净值和汇率都应通过独立的数据源适配层获取。

即使外部接口暂时不可用，用户仍然可以：

* 查看上次缓存的数据
* 手动输入价格
* 手动输入净值
* 手动输入汇率
* 正常查看历史资产记录

## 五、目标用户

### 5.1 核心用户

拥有以下一种或多种资产的长期投资者：

* A 股
* 美股
* 中国境内基金
* QDII 基金
* 人民币资产
* 美元资产
* 多券商账户

### 5.2 用户特征

核心用户通常具有以下特点：

* 不频繁交易。
* 更关注长期资产变化。
* 不需要秒级行情。
* 重视资产隐私。
* 希望脱离单一券商平台。
* 希望长期保存自己的投资数据。
* 希望清楚了解不同币种换算后的总资产。

## 六、主要使用场景

### 场景一：查看全球总资产

用户打开首页后，可以立即看到：

* 人民币口径总资产
* 美元口径总资产
* 各账户资产
* 各币种资产
* 当前总盈亏
* 数据最后更新时间

### 场景二：录入 A 股持仓

用户选择一个国内券商账户，录入：

* 股票代码
* 股票名称
* 持仓数量
* 成本价格

系统根据账户类型自动确认市场和交易币种，并通过行情数据源获取当前价格。

系统自动计算：

* 持仓成本
* 当前市值
* 持仓盈亏
* 盈亏比例

### 场景三：录入嘉信理财美股持仓

用户选择嘉信理财账户，录入：

* 美股代码
* 持仓数量
* 美元成本价

系统通过行情数据源获取当前美元价格。

系统计算美元口径下的市值和盈亏，并根据汇率换算成人民币。

### 场景四：录入场外基金

用户录入：

* 基金代码
* 基金名称
* 基金份额
* 持仓成本
* 最新净值
* 净值币种
* 净值日期

基金可以是：

* 人民币份额
* 美元份额

### 场景五：行情接口失效

当某一行情接口不可用时：

* 系统显示上次成功获取的价格。
* 标记价格更新时间。
* 提示当前数据可能已过期。
* 用户可以切换数据源。
* 用户可以手动修改价格。

### 场景六：备份和恢复数据

用户可以将全部本地数据导出为备份文件。

更换浏览器或设备后，用户可以导入备份文件，恢复账户、持仓和历史数据。

## 七、MVP 功能范围

MVP 的目标是先解决“统一记录和统计资产”的问题。

### 7.1 首页仪表盘

首页需要展示：

* 人民币口径总资产
* 美元口径总资产
* 总持仓成本
* 总浮动盈亏
* 总盈亏比例
* 人民币资产占比
* 美元资产占比
* 各账户资产占比
* 各资产类型占比
* 最近一次行情更新时间
* 最近一次汇率更新时间

### 7.2 账户管理

用户可以创建、修改和删除账户。

账户字段包括：

* 账户名称
* 账户类型
* 所属市场
* 默认币种
* 备注

账户类型示例：

* A 股券商
* 美国券商
* 基金平台
* 银行账户
* 现金账户
* 其他

账户示例：

* 招商证券
* 嘉信理财
* 天天基金
* 人民币现金
* 美元现金

### 7.3 持仓管理

用户可以新增、编辑和删除持仓。

持仓支持以下资产类型：

* 股票
* ETF
* 场外基金
* 现金
* 其他资产

通用持仓字段：

* 所属账户
* 资产代码
* 资产名称
* 持仓数量或份额
* 成本单价
* 当前价格或净值
* 价格更新时间

资产类型、市场和币种由页面分区与账户类型确定，不在股票新增表单中重复录入。

系统自动计算：

* 持仓总成本
* 当前市值
* 浮动盈亏
* 盈亏比例
* 人民币折算市值
* 美元折算市值

### 7.4 股票持仓

股票持仓字段包括：

* 股票代码
* 股票名称
* 持仓数量
* 成本价格
* 自动获取的当前价格

初期支持市场：

* 中国 A 股
* 美国股票市场

### 7.5 基金持仓

基金持仓字段包括：

* 基金代码
* 基金名称
* 基金份额
* 持仓成本
* 最新净值
* 净值币种
* 净值日期

初期支持：

* 人民币份额基金
* 美元份额基金
* QDII 基金

### 7.6 现金资产

用户可以在账户中记录现金。

现金字段包括：

* 所属账户
* 币种
* 金额
* 备注

例如：

* 嘉信美元现金
* 券商人民币现金
* 银行人民币现金

### 7.7 汇率管理

系统至少支持：

* USD/CNY
* CNY/USD

汇率更新方式：

* 自动更新
* 手动刷新
* 手动输入

汇率数据需要保存：

* 当前汇率
* 数据来源
* 更新时间

用户可以选择默认统计币种：

* 人民币
* 美元

首页同时展示人民币和美元两个口径的总资产。

### 7.8 行情更新

MVP 不要求秒级实时行情。

推荐更新方式：

* 用户手动点击“更新行情”
* 启动应用时按需更新
* 每隔一定时间低频更新
* 收盘后更新

建议默认更新频率：

* A 股：15 至 30 分钟，或收盘后每日一次
* 美股：15 至 30 分钟，或收盘后每日一次
* 场外基金：每日一次
* 汇率：每日一次，或手动更新

每条价格数据都必须展示更新时间。

### 7.9 手动价格模式

当前 MVP 的股票、ETF 和基金价格优先通过公开数据源自动获取，新增股票持仓时不要求用户手动录入当前价格。

当自动数据源失效时，系统应保留上次成功获取的价格，并明确提示价格缺失或过期。后续版本可以补充手动价格兜底能力。

手动录入的数据需要标记为：

* 手动输入
* 自动获取

### 7.10 数据导入与导出

MVP 支持：

* 导出完整备份文件
* 导入完整备份文件
* 导出持仓 CSV
* 导入持仓 CSV

备份内容包括：

* 账户
* 持仓
* 价格缓存
* 汇率缓存
* 用户设置
* 历史快照

## 十、核心计算规则

### 10.1 持仓总成本

持仓总成本等于：

持仓数量乘以平均成本价格。

### 10.2 当前市值

当前市值等于：

持仓数量乘以当前价格。

基金使用基金份额乘以最新净值。

### 10.3 浮动盈亏

浮动盈亏等于：

当前市值减去持仓总成本。

### 10.4 盈亏比例

盈亏比例等于：

浮动盈亏除以持仓总成本。

### 10.5 人民币折算

美元资产人民币市值等于：

美元市值乘以 USD/CNY 汇率。

### 10.6 美元折算

人民币资产美元市值等于：

人民币市值除以 USD/CNY 汇率。

### 10.7 数据过期判断

系统根据资产类型判断数据是否过期。

建议规则：

* 股票价格超过一个交易日未更新：提示可能过期
* 基金净值超过两个自然日未更新：提示可能过期
* 汇率超过一个自然日未更新：提示可能过期

节假日和非交易日需要避免错误提示。

## 十一、本地存储方案

由于产品计划通过 GitHub Pages 发布，因此 MVP 推荐采用：

* 前端框架
* IndexedDB
* 本地缓存
* JSON 或 ZIP 备份文件

GitHub Pages 是静态网站托管服务，不能直接运行本地服务器，也不能直接使用需要原生运行环境的 SQLite。

因此：

* GitHub Pages 网页版本优先使用 IndexedDB。
* 数据保存在用户当前浏览器中。
* 用户清除浏览器数据时，本地资产数据可能丢失。
* 产品必须提供明显的备份提示。
* 产品必须支持导入和导出。

未来可以额外开发桌面版本。

桌面版本可以采用：

* Electron
* SQLite

网页版和桌面版应尽量共用业务逻辑和界面代码。

## 十四、非功能需求

### 14.1 隐私

未经用户明确同意，不上传用户持仓和资产信息。

### 14.2 性能

在以下数据规模下，主要页面应流畅运行：

* 100 个账户以内
* 1,000 条当前持仓以内
* 10 年每日资产快照
* 100,000 条以内历史数据

### 14.3 可用性

即使行情接口失效，系统也不能无法启动。

系统必须优先加载本地数据，再尝试更新远程数据。

### 14.4 可维护性

数据源、计算逻辑、存储逻辑和界面展示需要分层。

不得将第三方接口请求散落在页面组件中。

### 14.5 可扩展性

未来应能够增加：

* 港股
* 日本股票
* 欧洲股票
* 债券
* 黄金
* 加密资产
* 房产
* 负债
* 股息
* 手续费
* 税费

## 十七、MVP 验收标准

满足以下条件时，MVP 可以视为完成：

1. 用户可以创建 A 股券商、嘉信和基金账户。
2. 用户可以录入 A 股、美股和场外基金。
3. 用户可以录入人民币和美元现金。
4. 系统可以正确计算每个持仓的成本、市值和盈亏。
5. 系统可以按人民币统计总资产。
6. 系统可以按美元统计总资产。
7. 系统可以展示各账户资产。
8. 系统可以展示各币种资产。
9. 用户刷新页面后数据仍然存在。
10. 用户可以导出全部数据。
11. 用户可以通过导入文件恢复全部数据。
12. 断网时仍可查看和修改本地资产。
13. 行情数据过期时有明确提示。
14. 行情接口失效时，用户可以手动输入价格。
15. 项目可以通过 GitHub Pages 正常访问。

## 二十、待确认事项

以下事项将在后续版本中进一步确认：

* 项目最终名称
* 使用 Vue、React 或其他前端框架
* 是否优先支持手机端
* 是否制作桌面客户端
* A 股默认数据源
* 美股默认数据源
* 基金净值默认数据源
* 汇率默认数据源
* 是否记录每笔交易
* 是否只记录当前持仓
* 是否计算已实现收益
* 是否记录分红、手续费和税费
* 是否支持账户内部不同币种
* 资产快照的生成时间
* 备份文件是否加密
